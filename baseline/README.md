# Baseline: vspark's algorithmic MediaPipe → VRM solver

A frozen copy of the owner's current tracking solver from vspark, runnable on its own. It is the
comparison baseline for the evaluation harness (PLAN.md §6, milestone M0). Do not improve it here.
Changes to vspark after the snapshot are not picked up.

## Usage

```sh
pnpm install
pnpm run-baseline --input frames.jsonl --output poses.jsonl            # backend solver output
pnpm run-baseline --input frames.jsonl --stage rendered --render-hz 60 # + frontend One Euro filter
pnpm run-baseline --poses poses.jsonl --stage rendered                  # filter only, any pose track
pnpm test                                                               # equivalence with vspark
```

Input is one JSON object per line: `{ t, pose?, face?, leftHand?, rightHand? }`, with `t` in
milliseconds and landmarks as vspark's camera code sends them: mirrored frame, pose world
landmarks with image-space visibility, hand world landmarks, image-space face landmarks. Landmarks
may be `{x,y,z,visibility?}` objects or `[x,y,z,visibility?]` arrays. Output is one
`{ t, bones: { <vrmBone>: [x,y,z,w] } }` per line: VRM normalized local bone rotations.

Calibration: `--capture-head-at <ms>` / `--capture-fingers-at <ms>` press the capture buttons at
that time; `--calibration file.json` loads saved offsets (`{ head?: {...}, fingers?: {...} }`,
same shape as vspark's `body_calibration` node state).

## What is reproduced

The pose branch of vspark's `MEDIAPIPE_PIPELINE_TEMPLATE` in its default quaternion-arm mode:
torso/head, arms with the elbow-hinge solve, confidence-weighted arm smoothing, both hands, merge,
head calibration and finger calibration. All behaviour-config values are vspark's defaults.

The optional rendered stage adds the frontend's per-bone One Euro filter (min cutoff 1.0, beta 0.3).
`--poses` skips the solver and runs a precomputed pose track (another system's output, same format)
through this stage only, so other systems get identical filtering.
It runs once per simulated render frame on the latest pose, as vspark's Viewport does. The
second-order dynamics filter is available but off, matching vspark's default.

Faithfully reproduced quirks:
- **Stale streams.** vspark only sends a hand or face stream when it is detected, and the graph
  keeps the last value. A hand that leaves the frame keeps driving the solver with its last
  landmarks. `--no-hold-missing` turns this off for experiments.
- **Pose-gated output.** Frames without pose landmarks produce no output.
- vspark's camera runs at 320×240, throttled to 10 FPS, on mirrored frames. That happens before
  this code, so recordings must be made the same way to be comparable.

## Not reproduced

- Face blendshapes (the ARKit heuristic and the mapper chain). Not part of the bone solve.
- IK arm mode (`useIk`), off by default in vspark.
- vspark's broadcast bus, Tracking Mix weights, animation blending, tracking-loss fades and
  avatar compose levers. The rendered stage is the One Euro filter only.

## Verification

`test/equivalence.test.ts` compares the driver against reference output generated by vspark's real
signal-graph engine on the same input: four recorded webcam clips from vspark's test fixtures, plus
a synthetic clip that adds face landmarks. Each clip runs with and without a head calibration
capture. The driver matches to the last bit: 250 frames, zero difference. Negative controls
(disabling the stale-stream hold, switching to the legacy arm solve) produce clear mismatches, so
the comparison is not vacuous. The rendered stage has only sanity tests; vspark's Viewport cannot
run headless.
