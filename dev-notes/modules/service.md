## Merger runtime (implemented 2026-11-14, owner's live test pending)
Branch `feature/merger-runtime` (with `feature/legs-root`; the relational-retarget prototype came along but was not used by the runtime) merged into `dev` and `main` 2026-11-14; part of v0.1.0. Decisions: `PLAN.md` §7.6.
- Default model: the merger bundle `data/merger/runs/mg3/live` (written by `mttrain.merger.export`, `modules/merger.md`) when present, or `--merger DIR`. Run per detector frame by `mtcore.merged.LiveMerged` (`modules/mtcore.md`): body `m1-v14`, pair hand model `p3`, face-mesh head pose, base combination, merger. cli's `MergerModel` subclasses it.
- `--no-merger`: the old M1 lifter (`--bundle`, default `m1-v10`) with `hands.py` fingers, wrapped in `LiveMerged`'s shape; also the fallback when the default merger bundle is missing.
- Bones: 50 (body, legs, fingers). Legs on by default (vspark's mixer can zero their influence, owner 2026-11-14); `--no-legs` drops them for other consumers.
- Hip position and up direction: `/MT/Root`, `/MT/Up` (see VMC conventions). vspark ignores them for now. `--dump-poses` records root/up.
- Cost: model ~2.4 ms/frame on one core (after batching `MhrToVrm`, was 8.0), MediaPipe ~20 ms. Run on the seated-v1 video: 50 bones at 10 Hz.
- Known model caveats (from the evaluations, `plans/legs-root.md`): `m1-v14` depth reads 10-50% too far; `mg3` regresses on the pairs3 two-hand set and its thighs are 2-6 deg worse than `m1-v14`; `m1-v14` head 1-2.5 deg worse on some render sets.

## Live retargeting (implemented, merged into `dev` 2026-11-17; off by default)
Branch `feature/runtime-retarget` (started 2026-11-16, merged into `dev` 2026-11-17, not yet released). Decisions: `PLAN.md` §3.10a ("Runtime retargeting, first live step"). Wires `mtcore.relretarget.LiveRetarget` (`modules/mtcore.md`) into `LiveMerged` and `cli.py`; merger runtime only (not `--no-merger`).
- Setup: a VRM avatar (`--avatar-vrm` or the stdin `avatar` command's `vrm_path`) always gets a retargeting built (`LiveMerged.set_avatar_vrm`, ~165-265 ms per avatar) when the bundle has `retarget.npz`. An avatar given as `rest_positions` only has no mesh: no retargeting. Without a VRM: default reference rest pose, rotation copy.
- Switch: applied only while on. **Off by default** (rotation copy); `--retarget` starts with it on; the stdin `retarget` command toggles it live. A request without a VRM avatar stays requested and applies once one is set. vspark's Learned Tracking sends the command from its "Fit to the avatar's proportions" checkbox (vspark `feature/learned-tracker`, 9ae36c8f).
- Setup failures leave the rotation copy; the message is kept in `LiveMerged.retarget_error`, logged, and sent as an `error` event when retargeting is on.
- Human side: MHR's mean body (rest vertices + VRM body-part labels), `retarget.npz` in the merger live bundle, written by `mttrain.retarget_asset` (the runtime has no pymomentum). See Releases: not yet part of `mttrain.merger.export`.
- Cost: ~5 ms/frame on one core (matrix FK on the needed bones only).
- Why off by default (measured on renders with the Fenn_2 avatar): helps separated hands (2-3 cm), makes touching hands worse (the tracked pose's gap on MHR's mean body is carried over), hand-to-face unchanged (tracking error). The owner compares on/off live in vspark (pending).
- Later step, only if it helps live: per-avatar extra VMC outputs (planned).

## Face and fingers (implemented 2026-11-12, owner's live test pending)
Plan: `plans/m2-face-hands.md` (steps 1-4 done, numbers in its Progress section); decisions: `PLAN.md` §7.5. Branch `feature/m2-face-hands` (commits 1f7f7db, ec0904d).
- Face: Holistic's own blendshape output (`output_face_blendshapes`, same model as Face Landmarker's) → 52 ARKit values (0..1), observation key `blendshapes`, sent as `/VMC/Ext/Blend/Val`. `--face-mesh full` (default) uses a cached copy of the pinned Holistic bundle with the pinned Face Landmarker bundle's full face mesh swapped in (closer to Face Landmarker than stock Holistic); `lite` = stock Holistic; `--no-face` disables. Left/Right names are passed on as MediaPipe gives them: like the bones they mirror the person (pose "left" is the person's right on the mirrored frames), as in vspark's MediaPipe Tracking.
- Fingers: `hands.py`, line-for-line port of vspark's `hand_landmarks_to_bones` (finger bones only, no wrist, from hand world landmarks), within 3e-6 deg of the TypeScript. Sent only for hands seen in that frame; `--no-fingers` disables. No smoothing, matching vspark's graph.
- Cost: about 0.7 ms/frame for face and fingers together.
- vspark side (vspark `feature/learned-tracker`, not pushed): the VMC receiver takes `Blend/Val` with ARKit names into its ARKit chain on `Blend/Apply`; other names are ignored.
- Open: finger calibration (Learned Tracking's graph has no `finger_calib`; ask after the live test).

## Face post-processing (implemented 2026-11-14, merged into `dev` 7602316)
Owner decision 2026-11-14 (`PLAN.md` §3.11/§7.5): algorithmic correction first, learned face head in reserve. Owner-approved as good enough for vspark use; Learned Tracking runs it live with no vspark change (eye filter and 60 Hz face stream are on by default; vspark's VMC receiver handles the separate `Blend/Val` + `Apply` packets independently of the bone packets). The filter itself is `mtcore.face_filter` (`modules/mtcore.md`).
- `face.py` `FaceStream`: eye correction (`EyeFilter`) per detector frame, then a thread sends the glided blendshapes at `--face-rate` Hz (default 60) via `VmcSender.send_blend` (`Blend/Val` + `Blend/Apply`; the socket is guarded by a lock). Bones still go out once per detector frame, now without blendshapes. `--face-rate 0` = blendshapes per detector frame (for receivers that interpolate themselves). Whether vspark should also interpolate on its side: `[OPEN]`.
- `--no-eye-filter` turns the eye correction off; `--dump-landmarks` keeps the raw values.
- Videos run without `--realtime` have no wall clock: no stream thread, the processed blendshapes go out with each frame.
- `faceproc.py`: offline, a landmarks dump → 60 Hz blendshape JSONL for `tools/avatar-video/prepare.py --blendshapes`. Comparison videos (raw vs processed face, same body): `data/videos/{seated-v1,hands-v1}-face/`.
- Live check (hands session video, `--realtime`): bones 10 packets/s, face 60/s, resting blink 0.08/0.06.

Dependencies: `mtcore` without the `mhr` extra (numpy-only modules, `modules/mtcore.md`), mediapipe 0.10.18, onnxruntime, opencv-contrib-python. No torch, no pymomentum, no MHR assets: everything model- and skeleton-specific comes from the bundle written by `mttrain.export` (`modules/train.md`).

## Structure
| File | Role |
|---|---|
| `detector.py` | `Detector`: Holistic Landmarker set up like the recorder (same pinned `.task` model, VIDEO mode, same confidence options, mirrored 320x240 via `prepare`). Model downloaded once to `~/.cache/motiontracker/` (MD5 checked) unless `--task` is given. Reads each output stream itself: 0.10.18's Python Holistic wrapper aborts on an empty packet (no hand) and drops everything without a face (`spikes/mp-python-parity/README.md`). Also blendshapes; `model_path(face_mesh="full"\|"lite")` builds and caches the full-mesh bundle (`~/.cache/motiontracker/holistic_landmarker-float16-1+face_landmarker-float16-1-mesh.task`). |
| `sources.py` | Frame sources yielding `(t seconds, BGR frame)` at 10 FPS. `CameraSource`: reader thread keeps only the newest frame, taken every 1/fps s like the recorder's throttled loop. `VideoSource`: the recorder's stepped replay (`ts = k/fps + 1 ms`, latest frame at or before `ts`), deterministic; `realtime=True` paces it to the wall clock. `list_cameras()` (Linux: sysfs names). |
| (`mtcore.merged`) | `LiveMerged(bundle)`: the merger runtime model (`modules/mtcore.md`); `cli.MergerModel` wraps it. |
| `lifter.py` | `LiveLifter(bundle)` (used by `--no-merger`): checks the bundle's input layout against `mtcore.features`, then per frame `mtcore.features.StreamFeatures.push` → ONNX → `mtcore.lifter_pose.LifterPose` (restricted to the output bones, 18 of 127 MHR joints) → `(bones, confidence, present)`. `set_avatar(rest_positions | None)`, `reset()` (on camera switch). |
| `hands.py` | `solve_hands(obs)`: port of vspark's finger solve (`hand_landmarks_to_bones`) → VRM finger bone rotations. Reference: `baseline/src/hands-cli.ts` runs the frozen TS node over JSONL frames. |
| `face.py` | `FaceStream`: eye correction + glided blendshape stream on its own thread (see Face post-processing). |
| `faceproc.py` | Offline face post-processing of a landmarks dump → 60 Hz blendshape JSONL for the avatar video. |
| `preview.py` | `Preview`: camera preview for the stdio parent (JPEG of the detector input and/or 2D landmarks per frame); see Camera preview. |
| `vmc.py` | Own OSC encoder (`message`, `bundle`) and `VmcSender` (`send` per frame, `send_blend` for the face stream). See VMC conventions. |
| `cli.py` | `mtservice` entry point and main loop; standalone or `--stdio`. `--dump-poses` / `--dump-landmarks` write JSONL for offline comparison; `--vmc off` disables sending; `--face-mesh`, `--no-face`, `--no-fingers`, `--face-rate`, `--no-eye-filter`, `--merger DIR`, `--no-merger` (+ `--bundle`), `--no-legs`, `--avatar-vrm FILE`, `--retarget` (see Live retargeting), `--fps N`, `--history-shift none|every|alternate` (see Frame rate). |

Default bundles: `data/merger/runs/mg3/live/` (merger), `data/m1/runs/m1-v10/live/` (`--no-merger`); gitignored, CMU-derived weights, never committed.

## Stdio protocol (`--stdio`)
JSON lines; stdout carries only events (MediaPipe and log output go to stderr). Authoritative list: `cli.py` docstring.
- Commands (stdin): `{"cmd":"avatar","vrm_path":"/abs/avatar.vrm"}` (rest pose and retargeting from the file) or `{"cmd":"avatar","rest_positions":{vrmBone:[x,y,z]} | null}` (null = bundle's default avatar, AvatarSample_D; no retargeting), `{"cmd":"retarget","enabled":bool}` (retargeting on/off, see Live retargeting), `{"cmd":"camera","index":n}` (ignored for video sources), `{"cmd":"cameras"}`, `{"cmd":"preview","image":bool,"landmarks":bool}` (camera preview on/off, both false = off; see Camera preview), `{"cmd":"fps","value":n}` (1..60), `{"cmd":"history_shift","mode":"none"|"every"|"alternate"}` (see Frame rate), `{"cmd":"stop"}`.
- Events (stdout): `ready` (model source, bones, source, `face`: "full"|"lite"|null, `fingers`: bool, `legs`: bool, `merger`: bool, `retarget`: bool = active), `retarget` (`enabled` = requested, `active` = applied, `reason`: why requested but not applied (no merger / needs a VRM avatar / setup failed) or null; sent after `ready`, after every `avatar` command and every `retarget` command), `status` (~1/s: fps, detect_ms, model_ms (includes the finger solve), latency_ms capture → output, present fraction), `cameras`, `preview` (per processed frame while the preview is on; see Camera preview), `settings` (`fps`: n, `history_shift`: str or null; after `ready` and after each `fps`/`history_shift` change), `error`, `stopped` (reason).
- Closing stdin stops the runtime, so it never outlives its parent. Unknown or malformed commands produce an `error` event, not an exit.

### Camera preview (implemented 2026-11-23, released in v0.3.0)
The runtime holds the webcam, so the parent (vspark) cannot show a camera preview itself; it asks the runtime for frames instead. `preview.py` (`Preview`), test `tests/test_preview.py`.
- Off until the stdin `preview` command turns on `image` and/or `landmarks`; both false turns it off. Only emitted with `--stdio`.
- While on, one `preview` event per processed frame (~10/s), sent after the VMC send in the `cli.py` frame loop (which keeps `rgb = prepare(frame)` for it): `{"event":"preview","t":ms,"width":320,"height":240,"mirrored":true,"image":<base64 JPEG>,"landmarks":{...}}`.
  - `image` (if requested): base64 JPEG, quality 70, ~6 KB, of the exact detector input (the mirrored 320x240 frame from `detector.prepare`).
  - `landmarks` (if requested): `pose` `[[x,y,visibility]]` x33, `leftHand` / `rightHand` `[[x,y]]` x21, `face` `[[x,y]]` x478; normalized image coordinates of that mirrored frame. Streams not detected in the frame are left out. Left/right are MediaPipe's labels on the mirrored frame.
  - ~16 KB per event with both.
- vspark side (branch `feature/learned-tracker`, b3dc60ba): floating "Camera preview" window opened from the Learned Tracking properties, Picture/Landmarks checkboxes; the backend requests the union of what open windows want and forwards frames only to them.

### Frame rate (implemented 2026-11-23, released in v0.4.0)
Commits 7941a68 (frame rate), 247f222 (history shift). Decisions and measurements: `PLAN.md` §7.7.
- `--fps N` (default 10) at start, or the stdin `fps` command live (1..60): changes `CameraSource.interval` / `VideoSource.step`. The models were trained at 10 FPS; their histories are picked by age (`mtcore.merged` / `features`, `modules/mtcore.md`), so 10 FPS output is bit-identical to v0.3.0.
- `--history-shift none|every|alternate` (default `none`) or the stdin `history_shift` command: `LiveMerged.history_shift`, against the frame-to-frame alternation at 20 FPS. Experiment; the owner is comparing the modes live in vspark.
- The `settings` event reports both after `ready` and after each change.
- Measured: end-to-end latency (rendered arm, halfway) 107 ms at 10 FPS → 57 ms at 20; runtime CPU 82% of one core at 20 FPS (about half at 10); accuracy unchanged; visible shake grows with rate. Details in `PLAN.md` §7.7.

## VMC conventions
- One OSC bundle per frame: `/VMC/Ext/OK 1`, `/VMC/Ext/T`, `/VMC/Ext/Root/Pos` (identity), one `/VMC/Ext/Bone/Pos` per output bone, then the extensions.
- Bone names: Unity HumanBodyBones (`UNITY_NAMES`): hips, spine, chest, upperChest, neck, head, shoulders, upper/lower arms, hands, legs (UpperLeg, LowerLeg, Foot, with rest offsets), finger bones. Bones without a Unity name are skipped. Thumb: Unity's Proximal/Intermediate/Distal = VRM 1.0 Metacarpal/Proximal/Distal. `VRM_PARENT` covers the finger chains for rest offsets.
- Rotation sent as `(x, -y, -z, w)`: vspark's `rhylive_bone_mapper` applies the same self-inverse map, so vspark receives exactly the lifter's VRM normalized locals. Positions: the avatar's rest offsets from the nearest present parent (`rest_offsets`), mapped `(-x, y, z)`.
- Blendshapes: one `/VMC/Ext/Blend/Val <ARKit name> <v>` per shape, then `/VMC/Ext/Blend/Apply`; by default in their own packets at `--face-rate` (60 Hz), not in the bone bundle.
- Extensions: `/MT/Present 0|1`, `/MT/Conf <lifter joint> <0..1>` (confidence = exp(-log_scale)), `/MT/Root x y z` (hip position, m) and `/MT/Up x y z` (unit up direction), both in the body model's camera frame (x right in the mirrored image, y down, z away), not vspark's pose space; `Root/Pos` stays zero (`[CLAUDE]`, `PLAN.md` §7.6). Namespace `/MT/` is provisional (`PLAN.md` §7.2, `[OPEN]`); receivers ignore unknown addresses.
- No smoothing of bones: they go out as is at 10 FPS (blendshapes are glided, not smoothed, see Face post-processing). Whether vspark smooths VMC input (the model was judged through glide) is an open question in the plan.

## Extending
- **New frame source**: a class with `__iter__` yielding `(t seconds, BGR frame)` at the lifter's frame rate (10 FPS; the model's history offsets assume it) and `close()`; `CameraSource` also exposes `t0` for the latency stat. Wire it into `open_source` in `cli.py`. Keep the recorder's capture settings (mirroring happens in `detector.prepare`).
- **New output sink** (e.g. the deferred WebSocket): take `(t, bones, conf, present)` per frame like `VmcSender.send`, plus a rest-pose update hook if it sends positions; call it from the main loop next to `vmc.send`. New VMC extension addresses go under the same (provisional) namespace.
- **New merger bundle**: export with `mttrain.merger.export`, then run `mttrain.retarget_asset` on the bundle dir (writes `retarget.npz`, needed for live retargeting; not part of the export yet), and pass `--merger DIR` (or replace the default run name `DEFAULT_MERGER` in `cli.py`). Changes to the chain go into `mtcore.merged` and must keep parity with `mttrain.merger.run.infer` (`--check`).
- **New bundle version**: `lifter.json` carries `"format": "motiontracker-lifter", "version": 1`. `LiveLifter` currently checks only the input layout (offsets, frame dim) against `mtcore.features`, not the version. When the bundle format changes (new inputs such as hands/face, other output bones), bump `version` in `mttrain.export` and branch on it in `LiveLifter`; feature changes go into `mtcore.features` so training, export and runtime stay identical.
- **New output bones**: come from the bundle (`output_bones`); add their Unity names to `vmc.UNITY_NAMES` and parents to `vmc.VRM_PARENT`.
- **Learned hand model** (`p3`): runs inside the merger runtime (`mtcore.merged`), not as a separate runner; `hands.py` remains for `--no-merger`.
- **Learned face path** (`PLAN.md` §3.11/§7.5): may replace the MediaPipe blendshapes or consume them (e.g. as merger input); keep the `{ARKit name: 0..1}` observation key so `vmc.py` is unchanged.
