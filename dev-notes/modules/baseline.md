# baseline

Status: implemented (frozen). Usage, input/output format, what is and isn't reproduced, verification and the full provenance table: `baseline/README.md` (authoritative). This file covers structure and how to work with it.

## Structure

Own package: pnpm, TypeScript, tsx, vitest, three ~0.168. Path aliases `@vspark/shared/*` are defined in both `tsconfig.json` and `vitest.config.ts` (keep them in sync).

- `vendor/` — byte-identical copies of the vspark working tree (snapshot details in the README):
  - `shared/` — vspark shared types/signal/node infrastructure, plus two type-only stubs (`types.ts`, `style_rig.ts`) that are the only non-copied files.
  - `backend/signal/nodes/` — the 7 solver nodes; `backend/signal/mocap_torso.ts`; `backend/mediapipe_tracker_graph.ts` (graph constants).
  - `frontend/` — `oneEuroFilter.ts`, `secondOrderDynamics.ts`.
- `src/pipeline.ts`
  - `BaselineSolver`: wires the nodes like the pose branch of vspark's `MEDIAPIPE_PIPELINE_TEMPLATE`, using a minimal bind context that mirrors vspark engine semantics: config fallback when an input is unconnected or undefined, list inputs drop undefined entries, a throwing pull yields undefined. Pins `Date.now` to the frame's `t` so time-dependent nodes are deterministic.
  - `renderStage`: frontend per-bone One Euro filter, applied once per simulated render tick on the latest pose.
  - `holdMissing` (default on): reproduces vspark keeping the last hand/face landmarks when a stream drops out.
- `src/cli.ts` — JSONL in/out CLI, `pnpm run-baseline`. Output is `OutputFrame` JSONL: `{t, bones:{vrmBone:[x,y,z,w]}}`, the format the planned eval-harness will consume.
  - WIP (2026-11-07): filter-only mode — input is a precomputed `OutputFrame` pose track instead of landmarks; only `renderStage` (One Euro, 60 Hz) runs, matching the `baseline-rendered` stage. Used to render learned-model output (e.g. M1) for comparison; see `eval-harness.md`. Exact CLI flag/interface not yet documented.
- `test/equivalence.test.ts` + `test/fixtures/` — bit-exact comparison against `expected_outputs.json`, which was generated by vspark's real signal-graph engine: 250 frames incl. a synthetic face clip, each run with and without a head calibration capture.

## Rules / extending

- Never edit `vendor/` to "improve" the baseline. It is the reference to beat, not a component to tune.
- Changes to `src/pipeline.ts` must keep `pnpm test` bit-exact. Adding options (like `holdMissing`) is fine if the default reproduces vspark.
- Regenerating the snapshot (e.g. a newer vspark state): re-copy the vendored files from vspark, update the README provenance table (paths, state, hashes), and regenerate `expected_outputs.json` with vspark's engine. Do not regenerate expected outputs from this driver itself, that would make the test vacuous.
- Not covered by bit-exact tests: the rendered stage (sanity tests only; vspark's Viewport can't run headless).
